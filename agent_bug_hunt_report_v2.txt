HIGH
----
1. Selecting the "Manual" sort mode crashes the card list — const reassignment  [REPRO]
   cardManager.js:222 vs :246
   `_sortCards` declares `const sorted = [...cards]`, and the `case 'manual':`
   branch (added by the fix commit) executes `sorted = sorted.filter(...)`.
   Assignment to a const throws TypeError. 'manual' IS a real option in
   #cardSortSelect (index.html:113, also added by the fix), so the branch is
   reachable.
   Repro: load ≥4 cards → set sort to Manual → renderCardList throws
   "TypeError: Assignment to constant variable." at cardManager.js:246, the
   global error boundary shows a red error toast, and the list never renders.
   Worse, the mode stays 'manual', so EVERY subsequent renderCardList — card
   selection, creation (createNewCard throws mid-way: card is inserted into
   storage but never selected), drag-reorder, batch ops, cross-tab updates —
   fails until the user switches the sort back. `bun build` refuses to compile
   the file for the same reason.
   Fix: `let sorted` (or build a second array). One-word fix; blocks the Manual
   feature and drag-reorder (whose saved order is only honored in Manual mode).

2. Every evicted toast crashes Bootstrap ~5–300 ms later — error-toast cascade  [REPRO]
   ui.js:74-81 (showToast eviction), Bootstrap 5.3.3
   The eviction loop calls `inst.dispose()` on a toast whose `show()` transition
   callback is still pending. Bootstrap's BaseComponent.dispose() does
   `for (const t of Object.getOwnPropertyNames(this)) this[t] = null`, nulling
   `_element`. The deferred callback from show() (`executeAfterTransition`
   fallback timer, 5 ms for transitionless elements) then runs
   `this._element.classList.remove(...)` → "Cannot read properties of null
   (reading 'classList')" inside bootstrap.bundle.min.js.
   Repro: show 6 toasts in a burst (e.g. batch delete, rapid save toasts, AI
   errors); each of the 3 evicted toasts throws ~300 ms later (verified
   deterministically — 3 errors per 3 evictions). The global error boundary
   (setupErrorBoundary) converts each into another red "Unexpected error" toast,
   which can evict further toasts and re-trigger. The #77 fix added the explicit
   `hidden.bs.toast` dispatch and dispose call — dispose on a *shown* toast is
   the culprit; the countdown timer it tried to fix could be cleared by simply
   removing the element (the app's own hidden listener already clears it).
   Fix: don't dispose; just remove the element (the app listener on
   hidden.bs.toast clears the interval and removes it), or dispose after the
   show transition completes.

MEDIUM
------
3. On load, named providers inherit the *Custom* provider's API key  [code-verified]
   ui.js:410-412 (init)
   `AIService.setProvider(provider, provider === 'openrouter' ? apiKey : customKey)`
   — for xai/deepseek/zai/chutes/nanogpt the in-memory `_apiKey` is seeded with
   CardStorage.getCustomApiKey(). _getApiKeyForProvider() (aiService.js:59-63)
   prefers `this._apiKey`, so every request to e.g. api.x.ai carries the LM
   Studio/Ollama key (and the correct per-provider key is ignored) until the
   settings modal is opened/closed or refreshModelsList runs with an empty key —
   which only happens at init when an OpenRouter key or custom provider is set.
   Symptom: with provider = xAI + a custom key configured, all xAI calls fail
   auth with the wrong credential. The per-provider key refactor (fix for #29)
   missed this init path; the hidden.bs.modal handler at ui.js:658-662 and
   Settings.toggleProvider do it correctly.
   Fix: seed with `provider === 'openrouter' ? apiKey : (provider === 'custom'
   ? customKey : CardStorage.getProviderKey(provider))`.

4. Switching cards mid-generation lets the aborted run pollute the NEW card's chat  [code-verified]
   cardManager.js:472-478 (_doSelect) vs aiChat.js:186-221
   _doSelect calls AiChat._abortAll() on card switch but does NOT bump
   AiChat._gen (only send/retry/clear do — aiChat.js:154, :931, :1147). The
   aborted requests' `.then`/`.catch` check `gen !== this._gen` to bail, which
   passes because _gen is unchanged. In the multi-field path, if any field had
   completed before the switch, the stale `.catch` (aiChat.js:205-221) pushes
   `combinedContent` into window.AppState.chatHistory — now the NEW card's
   freshly-loaded history — and persists it via saveChatHistory (also calling
   _updateSession against the new card). The single-request path (_sendFullCard,
   aiChat.js:537) instead injects a spurious "Generation stopped." system bubble
   into the new card's view.
   Fix: `AiChat._gen++` (or call a shared AiChat.cancelRun()) alongside
   _abortAll() in _doSelect, same as clearChat/retryLastMessage.

5. A malformed-but-plausible lorebook entry breaks card selection entirely  [REPRO]
   editor.js:549-558 (renderLorebook), cardEngine.js:189 normalize()
   `const secondary = (entry.keysecondary || []); … secondary.slice(0, 2).map(…)`
   — if keysecondary is a string (legacy/odd cards; key already gets string-array
   normalization at :530-531, keysecondary does not), `.map` is not a function
   and renderLorebook throws. Because populateEditor → renderLorebook runs inside
   _doSelect (cardManager.js:523), the exception rejects selectCard: the card is
   set as active but the editor never populates, the list never highlights, and
   no toast explains why. The same throw breaks AiChat.tryApplyAIResponse →
   populateEditor and any editor refresh. `(entry.keysecondary || []).join(', ')`
   at editor.js:562 has the identical failure mode.
   Fix: normalize `entry.keysecondary` to an array in CardEngine.normalize (like
   alternate_greetings), or guard with Array.isArray at render time.

6. Server ignores the PORT default when the env var is set to empty/"0"  [REPRO]
   server.js:9 — `parseInt(process.env.PORT || '8182')`. If PORT is exported as
   "0" (as in this environment), Bun listens on a random port and the README's
   "http://localhost:8182" link lies. Not a real product bug (env was
   deliberately 0 here), noted for completeness — the console log line also
   can't print the actual bound port.

7. aiService.setApiKey() writes named-provider keys into the custom slot  [code-verified]
   aiService.js:72 — dead code today (no caller), but if ever invoked with
   provider=xai it would persist to CardStorage.setCustomApiKey instead of
   setProviderKey, resurrecting bug #29. Worth fixing while touching storage.

8. Diff CDN script has no version pin → SRI mismatch on republish  [code-verified]
   public/index.html:1177 — `https://cdn.jsdelivr.net/npm/diff/dist/diff.min.js`
   (no version) with a pinned integrity hash. jsDelivr "latest" rolls forward, so
   a republish breaks the SRI and the script is blocked (Diff undefined → diff
   view silently degrades to plain text via _renderDiff's guard). Pin the version
   (e.g. diff@5.2.1) or drop the integrity for this one script.

CRITICAL (found sweep 3, now fixed)
-----------------------------------
9. escapeAttr crashes on the numeric lorebook `order` — lorebook broken for
   EVERY card with entries  [REPRO, FIXED]
   ui.js:escapeAttr does `str.replace(...)`; the #55 XSS fix wrapped
   `entry.order ?? 100` in escapeAttr, and per the V2 spec `order` is a
   NUMBER → `(100).replace` → "TypeError: str.replace is not a function".
   renderLorebook → populateEditor → _doSelect all throw, so selecting ANY
   card with a character_book entry fails silently (no editor, no highlight,
   no toast). A numeric `key` (number 7) crashed the same way. Missed in
   sweep 1 because the first test card crashed earlier on keysecondary.
   Fix applied: escapeAttr coerces String(str) (keeping 0); editor.js +
   cardEngine.normalize() now normalize keysecondary to an array and coerce
   non-string keys; non-object entries become empty placeholders so indices
   stay aligned. Verified live: normal card (order:100) and malformed card
   (key:7, keysecondary:'a, b') both render.

10. Retrying an old message orphans newer grouped multi-field cards  [FIXED]
    aiChat.retryLastMessage removed DOM bubbles by historyIndex >= target,
    but multi-field grouped cards carry NO historyIndex, so they survived the
    retry and stayed on screen under the re-added prompt (history had been
    spliced). Fix: remove from the target user bubble's DOM position onward
    (DOM order == history order). Verified live with a fabricated transcript.

11. "Manual" sort re-added search/tag-filtered-out cards  [FIXED]
    cardManager._sortCards manual branch appended `extras` from the FULL
    index, undoing any active search/tag filter. Manual mode now just keeps
    index order (the caller has already filtered).

CRITICAL (found + fixed + verified live)
----------------------------------------
12. Every exported PNG is corrupt since the fix commit  [REPRO, FIXED]
    exportUtils.embedCharaChunk (the #33 chara-dedupe rewrite) reassembles the
    file from `kept` chunks, which the chunk walk collects starting at offset 8
    — the 8-byte PNG signature is never included. Result: the exported file
    starts with the IHDR length field ("0,0,0,13,IHDR..."), so it is not a
    valid PNG: image viewers and SillyTavern reject it, and the app's own
    parsePNG throws "Not a valid PNG file" on re-import. Every PNG export since
    3ae3a51 was silently broken. Fix: prepend bytes.subarray(0, 8) to the
    reassembled output. Verified live: chunk order IHDR,sRGB,IDAT,tEXt,IEND,
    single chara chunk, re-export delta 0, full parse round-trip recovers the
    card data.

MEDIUM (found + fixed + verified live)
--------------------------------------
13. Stale chat session forks a duplicate (AiChat._updateSession)  [REPRO, FIXED]
    When the current session is older than the 30-min SESSION_TIMEOUT, the else
    branch updated the STALE session's timestamp/history (making it look
    current again — defeating the timeout) AND created a new session with the
    identical full history. The history panel showed two identical
    conversations and storage doubled. Fix: only start the new session; leave
    the stale one untouched. Verified: stale session keeps its old messageCount,
    exactly one new session is created, and a fresh (within-timeout) session
    still updates in place without forking.

==========================================

NEW BUG (found via the new Playwright suite, fixed + verified)
--------------------------------------------------------------
14. Multi-file import via Browse/file-picker silently imports only the first
    file  [REPRO, FIXED]
    CardManager.handleFileSelect passed the LIVE FileList to the async
    processFiles and immediately reset `e.target.value = ''`; resetting the
    input empties the live FileList, so after the first `await` the for-of
    loop iterated nothing. Drag & drop was unaffected (dataTransfer.files is
    stable) — only the Browse path dropped files 2..N. Fix: snapshot
    Array.from(e.target.files) before resetting. Verified: 4-file picker
    import now yields 4 cards (this is exactly what the new smoke suite caught).

NEW BUG (found via spec cross-check, fixed + verified)
------------------------------------------------------
15. Spec-conformant lorebook entries lose their keywords on import  [REPRO, FIXED]
    character-card-spec-v2 (and SillyTavern world-info exports) name entry
    fields `keys` / `secondary_keys` / `insertion_order` / `enabled`, but the
    editor reads `key` / `keysecondary` / `order` / `disable`. normalize()
    copied character_book verbatim, so real cards rendered with no primary
    keywords, no secondary keys, order 100, and edits re-exported empty keys.
    Fix: normalize() maps the spec names onto the editor's names when the
    editor's are absent. Verified: a spec-named entry (keys + secondary_keys)
    now renders both keyword chips.
